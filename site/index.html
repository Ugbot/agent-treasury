Payments that follow the written rules.

Agent Treasury lets software agents pay for delivery jobs, fuel, merchants and refunds in Stripe test mode, but only when a written policy allows it, and it shows which clause and evidence decided each payment.

Agents that spend money need rules they can be checked against

Rules live in prose

Fuel caps, insurance requirements and refund terms are written down, then re-implemented ad hoc wherever money moves.

Conditions change mid-job

A route change can invalidate a driver's cover. Pending work has to be re-planned without weakening the rule.

Nobody can say why

After a payment, the useful question is which policy version and which evidence allowed it. The design answers that for every operation.

From input to evidence

Allow leads to a Stripe test-mode call. Hold waits for approval or missing evidence. Deny stops the payment. All three are recorded with the clause that decided them. Animation is illustrative.

Four scenarios the demo is designed around

Deliver and release

A customer test payment is collected. Early receipt outside the destination radius fails. A valid confirmation at arrival releases separate transfers to merchant and driver test accounts.

Fuel entitlement

An active, eligible driver buys fuel with a test Issuing card within a GBP 8 cap. Over-limit or wrong-merchant attempts are declined.

Replan on coverage change

A route change breaks Driver A's coverage. Dispatch and unused fuel authority are refused; the planner looks for another eligible driver or route, and never weakens the rule.

Cancel and refund

With no eligible driver before pickup, pending work is cancelled and the original test payment is refunded under REFUND-1.

Policy clauses

These are illustrative, configurable demo rules from the design docs. They are not legal insurance terms or a production policy.

Illustrative demo clauses
ClauseRuleEnforcement and evidence
DRIVER-1Only an assigned, approved driver may claim a job or its fuel allowanceAssignment version and driver identity/session
COVER-1Supplied coverage record must include job type, vehicle, goods value and every planned zone, and remain valid through expected completionVersioned demo insurer record (simulated; no real insurer integration)
TRAVEL-1Route must stay within the organisation's permitted zonesRoute-zone intersection and current simulated position; cover never overrides a prohibited zone
FUEL-1Active eligible job may receive up to GBP 8 at permitted fuel merchants; no spend while unassigned or after completionIssuing category/country controls plus local job policy and budget reservation
FUEL-2Fuel stop within 100 simulated metres of the approved route, with fresh position evidenceMap geometry and timestamp
RECEIPT-1Release requires the assigned driver, fresh position inside the destination radius and a fresh one-use recipient confirmationAssignment version, distance, receipt event ID, consumed nonce
PAY-1Pay approved merchant bill and driver fee once after delivery proof passes, within limitsOriginal order, approved amounts, operation IDs and ledger
APPROVE-1Amounts above the automatic limit need human approval for that operationApproval bound to amount, currency, recipient and policy version
REFUND-1A cancelled order before pickup is fully refunded if no recipient transfers have executedOriginal test charge, order state, remaining refundable amount

Planned stack

  • DBOSDurable execution and sagas for payment workflows.
  • CogneePolicy and decision memory, used for explanations.
  • Stripe test modePayments, Connect transfers, Issuing, refunds. Test keys only.
  • GOAP plannerApplication-owned planning that replans unfinished work.
  • ReactMap, policy and evidence console (Vite).

Python backend managed with uv. Each piece's status is tracked in the repository's README and tests, not on this page.

Run it

Requires uv, Node.js and a Stripe test-mode key if you want real test calls. Check the README for current status and exact environment variables.

git clone https://github.com/OWNER/agent-treasury
cd agent-treasury
cp .env.example .env     # add Stripe TEST keys only
uv sync
uv run pytest            # unit tests
cd frontend && npm install && npm run dev
